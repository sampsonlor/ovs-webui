| 路径 / 约束                        | 证据                                                                  | 结论与边界                                             |
| ---------------------------------- | --------------------------------------------------------------------- | ------------------------------------------------------ |
| Ports 对象 → VLAN 意图 → Candidate | 原型测试检查目标对象和禁止静默替换                                    | 状态层通过；没有真实 Port API                          |
| Candidate → Validate → Apply       | 空候选、未验证、缺原因、窄屏发起均被阻塞                              | 状态层通过；后端仍须独立检查                           |
| 活动事务 → Confirm → Evidence      | 完成后清候选，不允许再次确认/回滚                                     | 状态层通过；证据为会话 fixture                         |
| 重复点击/重复调用/活动中重暂存     | 同一事务期间不创建第二个 Job、不丢意图                                | 状态层通过；跨进程幂等尚待后端                         |
| Conflict                           | Base/Current/Mine，明确选择；Use mine 后验证失效                      | 状态层通过；数据库 CAS 待实现                          |

| Drift                              | 读取核对不产生配置写入，不与 Stale 合并                               | 状态层通过；实际观测未接入                             |
| OutcomeUnknown                     | 切回 Normal 不解除事务锁，四种核对结果不同处理                        | 状态层通过；fixture 选择器仅用于演示                   |
| 断线与截止时间                     | 断线禁用发送，离线到期不声称完成回滚                                  | 状态层通过；生产计时必须来自服务器                     |
| 回滚冲突                           | 不覆盖外部修改，继续锁住新的 Apply                                    | 状态层通过；真实 compare-before-rollback 未接入        |
| Standard / Expert                  | 同一个 transition 与写入门禁；新 API 不接受模式提权                   | 代码核对和请求 schema 检查通过；未做浏览器模式切换验收 |

| 响应式职责                         | 既有 desktop stage/start 门禁，现有事务共用入口                       | 状态层通过；设备、缩放和触屏验收待执行                 |

原型仍保留会话内状态和一个实际 `/` 路由；没有把本轮契约代码冒充成服务端持久化、浏览器刷新恢复或真实鉴权。

## 接入前已补充的约定与检查

| 可能导致联调误判的问题                          | 本轮处理                                                                              |
| ----------------------------------------------- | ------------------------------------------------------------------------------------- |
| 提交已接受但响应丢失，前端不知道 transactionId  | 引入持久化请求账本契约；辅助函数仅用原 requestId 读取恢复，测试确认只发生一次提交     |
| 查询 request 返回 404 就当作没有执行            | 明确保持未知；测试覆盖无记录、接收中、断线和错误节点响应                              |
| Applied 被直接当成 Confirmed                    | 区分 phase / knowledge / outcome / safeApply；Applied 且仍待确认必须保留 Candidate 锁 |
| 本地倒计时归零就展示 Rolled back                | 新接口映射只禁用决策并核对结果；不生成服务器终态                                      |
| 旧轮询覆盖较新的确认结果                        | 检查事务身份、候选版本和单调 sequence，忽略乱序旧快照                                 |
| 字符串 trunks、空 trunks 或原生值被误解释       | 请求使用规范化数组；空 Trunk 列表不接受；原生 All-VLAN 配置保留观察能力               |
| UI 的 mock reconciliation result 被送给真实后端 | schema 拒绝 result；真实结果只由后端返回                                              |
| Expert、force 或任意 userId 绕过写入限制        | 请求 schema 不接受这些字段；仍明确生产 RBAC 责任在服务端                              |

`lib/api/change-control.ts` 是独立、可测试的接入边界，尚未接替 `lib/change-control.ts` 原型 reducer。它依赖未来的 HTTP adapter 对 JSON 做运行时 schema 校验；接口示例不联系真实 OVS。
